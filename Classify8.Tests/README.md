# Classify8.Tests

xUnit + FlaUI (UIA3) によるテスト一式です。リポジトリのルートで `dotnet test Classify8.Tests/Classify8.Tests.csproj` を実行します。
UIテストを除いて実行する場合は `--filter "FullyQualifiedName!~FullUITests"` を付けます。

## テストの構成

### ユニットテスト (キーボード・マウスを使わない。まずこちらを実行)

| ファイル                      | 対象                                                                                                                                                     |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ParserTests.cs`              | 検索構文 (ワイルドカード、`?` が見た目の1文字に一致すること、AND/OR/NOT、括弧、空白と引用符、構文エラー、全角半角・かなの無視)、全体設定の NG キーワード |
| `SortRuleTests.cs`            | サイズ・タイムスタンプ条件、フォルダ判定、表記ゆれ設定の反映、濁点が分かれたファイル名、`Clone`                                                          |
| `LegacyImporterTests.cs`      | ClassiNy CSV の取り込み、キーワード変換、共通プリセットと有効/無効、変換結果が新しい構文で解釈できること                                                 |
| `FileProcessorTests.cs`       | 重複判定(完全一致・内容一致・連番違い・上限サイズ)、同名競合の解決、削除失敗、キャンセル、動的パス、フォルダ、**並列処理**(同名衝突・同一内容の同時投入) |
| `DynamicPathBuilderTests.cs`  | `/YYYY` `/FYYYY` `/NAME` `/COND` の展開と、フォルダ名に使えない文字の置換                                                                                |
| `FileContentComparerTests.cs` | 内容比較 (差が先頭・中間・末尾・バッファ境界にある場合、共有違反、キャンセル)                                                                            |
| `PathSafetyTests.cs`          | ドライブ直下・システムフォルダなど、危険な振り分け元の判定                                                                                               |
| `TextNormalizerTests.cs`      | 全角/半角、ひらがな/カタカナの正規化、濁点・半濁点の結合 (オプションに関係なく常に行う)                                                                  |
| `DataManagerTests.cs`         | ルール(CSV)・設定・プリセット(JSON)の保存と読み込みの往復、壊れたファイル、カルチャ非依存                                                                |
| `HistoryManagerTests.cs`      | 履歴の追記・時系列・件数上限・壊れたファイルの退避・読めないときの保護                                                                                   |
| `AtomicFileTests.cs`          | 一時ファイル経由の原子的な書き込み                                                                                                                       |

* `DataManagerTests` / `HistoryManagerTests` は、データの保存先を一時フォルダに差し替えて実行します(`AppPaths.DataDirectoryOverride`)。本物の設定・ルール・履歴には触れません。これらのテストは並列実行されません(`TestCollections.cs`)。
* ファイルを扱うテストは `%TEMP%` に専用フォルダを作り、終了時に削除します。

### UIテスト (`FullUITests.cs`)

実際にアプリを起動し、マウス・キーボードを操作します。

* **実行中は、マウス・キーボードに触れないでください。** 他のテストとは並列実行されません。
* 対話型のデスクトップ(ログインした画面)が必要です。CI などのサービス実行では動きません。
* 既存: ルールの追加と削除 / 設定画面 / コピー&ペースト / 入力エラー
* ドラッグ&ドロップ: 選択されていない行をそのまま掴んで並び替え / 選択済みの行を掴んで並び替え / チェックボックスを押しても選択中の行が変わらないこと
* 追加: 設定名・検索条件の構文・システムフォルダの入力チェック / ルールの実行(条件に合うファイルだけが移動) / 内容が同じファイルの重複処理 / ダブルクリック実行前の確認ダイアログ / 設定の保持 / 切り取りと貼り付け
* 設定を変えるテストは、終了時に必ず元の状態へ戻します。
* `UITestBase.cs` は、本体の exe を `Classify8.Tests` の出力フォルダ付近から自動で探します(従来の相対パスが使えるなら、それを優先)。
* **テストは、見つけた exe のフォルダを一時フォルダ(`%TEMP%\c8ui_app_*`)にコピーして、そこから起動します。** 本物の設定・ルール・履歴にテスト用のデータが書き込まれず、毎回まっさらな状態で始まります。終了時にコピーは削除されます。
* 新規ルールは「選択中の行の上」に挿入されるため、並び順を確認するテスト(ドラッグ&ドロップ、切り取り)は、追加した順序ではなく、画面上の実際の上下関係を読み取ってから操作します。
